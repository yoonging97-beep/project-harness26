# 작업 방식 — 신규 기능 설계 및 구현

> 이 문서는 "내가 실제로 어떻게 했는지"를 기록한다.
> "무엇을 위한 일인지"의 기준은 [story-service.md](story-service.md)에 있으며, 두 문서는 섞지 않는다.
>
> - story-service.md = 무엇을 만드는가
> - story-work.md = 그것을 포함해 신규 기능을 어떤 과정으로 만드는가
>
> 작업 도메인: 신규 기능 설계 및 구현
> 이번 적용 대상: 냉장고 돋보기

## 작업 문장

1. 기획자가 요청받은 신규 기능의 배경과 요구사항을 확인하고 요구사항 정의서를 작성한다.
2. 기획자가 요구사항을 정리하고 기존 정책과 충돌하거나 정의가 부족한 부분은 질문 목록으로 정리해 담당자에게 확인한 뒤 기능명세서를 작성한다.
3. 기획자가 기능명세를 바탕으로 사용자 흐름과 화면을 설계하고 화면설계서를 작성한다.
4. 기획자가 기능명세와 화면설계서를 검토해 정책 불일치, 누락된 상태와 예외 케이스를 수정한다.
5. 디자이너가 확정된 화면설계서를 바탕으로 UI 디자인을 제작하고 기획자가 요구사항과 일치하는지 검토한다.
6. 개발자가 확정된 기능명세서와 UI 디자인을 바탕으로 웹앱을 구현하고 기획자가 기능과 화면을 검수한다.
7. 기획자가 검수 결과를 디자이너와 개발자에게 전달하고 수정된 최종 웹앱을 확인한다.

## 흐름

```
요구사항 정의서 → G1 ─(NO)→ B0 ─┐
                   └(YES)────────┴→ 기능명세서 → 화면설계서 → G2 ─(NO)→ 수정 후 재검토
                                                               └(YES)→ B1 → UI 디자인 → G3 ─(NO)→ B2 → 재검토
                                                                                         └(YES)→ B3 → 웹앱 → G4 ─(NO)→ B4 → 재검수
                                                                                                                └(YES)→ 최종 웹앱
```

- 최종 웹앱은 별도 게이트가 아니라 G4를 통과한 결과로 본다.

## 입력 자료 (산출물 아님)

- 업무 요청서
- 기존 화면설계서 (있는 경우)

## 산출물

| # | 산출물 | 만드는 사람 | 구분 | 관련 문장 |
|---|---|---|---|---|
| 1 | 요구사항 정의서 | 기획자 | 중간 산출물 | 1 |
| 2 | 질문 목록 | 기획자 | 중간 산출물 | 2 |
| 3 | 기능명세서 | 기획자 | 산출물 | 2 |
| 4 | 화면설계서 (사용자 흐름 포함) | 기획자 | 산출물 | 3, 4 |
| 5 | UI 디자인 | 디자이너 | 산출물 | 5 |
| 6 | UI 디자인 검토 결과·수정 요청 | 기획자 | 중간 산출물 | 5 |
| 7 | 웹앱 | 개발자 | 산출물 | 6 |
| 8 | 검수 결과 | 기획자 | 중간 산출물 | 6, 7 |
| 9 | 최종 웹앱 | 개발자 | 최종 산출물 | 7 |

> 웹앱은 실제 구현 산출물의 기술적 형태다. 냉장고 돋보기는 모바일 사용을 전제로 한 웹앱/PWA로 구현한다.
> (서비스가 사용자에게 제공되는 형태인 PRD의 "모바일 앱"과 충돌하지 않는다.)

## 게이트 (판단 지점)

| # | 판단 | 통과하지 못하면 | 통과하면 | 관련 문장 |
|---|---|---|---|---|
| G1 | 요구사항·정책이 충분히 정의됐는가 | 질문 목록 작성 → B0 | 기능명세서 작성 | 2 |
| G2 | 기능명세와 화면설계가 일치하고 상태·예외가 빠지지 않았는가 | 화면설계서 수정 → 재검토 | 화면설계서 확정 → B1 | 4 |
| G3 | UI 디자인이 요구사항·화면설계와 일치하는가 | B2 → 수정된 UI 디자인 재검토 | UI 디자인 확정 → B3 | 5 |
| G4 | 구현된 웹앱이 기능명세·확정 UI대로 동작하는가 | B4 → 수정 → 재검수 | 최종 웹앱 확정 | 6, 7 |

| B1 | 확정된 화면설계서 | 디자이너 | UI 디자인 | 5 |
